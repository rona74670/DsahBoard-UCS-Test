❓ מה אומר כל מדד?

הסבר קצר ופשוט. לחץ על כותרת כדי לפתוח או לסגור. (Esc סוגר את החלון)
📊 הבסיס: CPU, RAM ופיק / ממוצע
CPU %
כמה מכוח המעבד שהוגדר לשרת הוא באמת משתמש בו. 100% = כל המעבדים של השרת עובדים בכל הכוח. גבוה לרגע זה לא בעיה; גבוה לאורך זמן = השרת צריך יותר מעבדים או שיש תהליך שתוקע אותו.
RAM %
כמה מהזיכרון המוגדר השרת משתמש בו באופן פעיל (זיכרון שהוא נוגע בו עכשיו, בלי מטמון). חשוב: זה לא אומר שהזיכרון נגמר. כדי לדעת אם חסר זיכרון, תסתכל על "לחץ זיכרון" למטה.
פיק
הדקה הכי עמוסה בטווח שבחרת (ומתי היא קרתה).
ממוצע
הרמה הרגילה של השרת לאורך הטווח. פיק גבוה + ממוצע נמוך = קפיצה חד-פעמית. פיק גבוה + ממוצע גבוה = שרת שעובד קשה כל הזמן.
vCPU / RAM (GB)
כמה מעבדים (וירטואליים) וכמה זיכרון הוגדרו לשרת.
מד עומס
סיכום מהיר: האם העומס הוא מקרי או חוזר.
🟢 תקין · ⚪ פיק חד-פעמי (נגע בעומס גבוה אבל לא חוזר) · 🟠 לתשומת לב (עומס בינוני לאחוז גדול מהזמן, או עומס גבוה בכמה שעות/ימים) · 🔴 בעייתי (עומס גבוה בחלק משמעותי מהזמן או שחוזר שוב ושוב). ריחוף על התג מסביר למה.
סף CPU / סף RAM
הערכים שמעליהם שרת נחשב "עבר את הסף" (ברירת מחדל 80% ו-85%). אפשר לשנות בשורת הסינון. הקו האדום המקווקו בגרף הוא הסף של ה-CPU.
⏱ CPU Ready — כשהשרת מחכה למעבד
מה זה
אחוז הזמן שהשרת רצה לעבוד אבל חיכה בתור למעבד פיזי פנוי על ה-ESXi. נמדד לכל vCPU.
איך קוראים את זה
🟢 מתחת ל-5% תקין · 🟠 5–10% אזהרה · 🔴 10% ומעלה קריטי (השרת מרגיש איטי).
ההבדל מ-CPU %
CPU % גבוה = השרת עובד קשה. Ready גבוה = ה-host עמוס מדי, גם אם ה-CPU % של השרת נראה נמוך. זה הסימן הקלאסי ל"שרת איטי בלי בעיית משאבים".
🧠 לחץ זיכרון — כשה-host מצר את הזיכרון של השרת
מה זה בקצרה
שלושה סימנים שה-host (ה-ESXi) לא נותן לשרת את כל הזיכרון שהגדרת לו כי הוא עצמו חסר זיכרון. 🟢 תקין · 🟠 אזהרה · 🔴 חמור.
Swap (🔴 חמור)
ה-host זרק חלק מהזיכרון של השרת לדיסק. דיסק איטי בהרבה מזיכרון, ולכן השרת מאט. כל ערך מעל 0 צריך תשומת לב.
Balloon (🟠 אזהרה)
ה-host "גוזל" זיכרון מהשרת דרך מנגנון בתוך המערכת. סימן שה-host מתחיל להיות במחסור, עדיין לפני swap.
Memory Latency
אחוז הזמן שהשרת מחכה לזיכרון בגלל דחיסה או swap. מ-1% אזהרה, מ-5% חמור.
חשוב לדעת
זה מראה רק לחץ שנגרם מה-host. שרת שהוגדר עם פחות זיכרון ממה שהאפליקציה צריכה (ומחליף זיכרון בתוך Windows/Linux) לא יופיע כאן; את זה רואים רק מתוך השרת עצמו.
🖥 ESXi — על איזה שרת פיזי השרת יושב
עמודת ESXi
שם ה-host הפיזי שהשרת רץ עליו עכשיו, עם נקודת צבע: 🟢 תקין · 🟠 עומס בינוני · 🔴 עומס גבוה · ⚫ לא זמין.
הכרטיס שנפתח מעל הגרף
CPU / RAM — כמה ה-host כולו עמוס. מ-75% CPU או 85% RAM אזהרה, מ-90% / 95% חמור.
CPU Ready ממוצע — כמה בממוצע השרתים על ה-host מחכים למעבד (מ-3% אזהרה, מ-5% חמור).
יחס vCPU:ליבה — כמה מעבדים וירטואליים חולקים כל ליבה פיזית. 4:1 אומר ארבעה מעבדים וירטואליים על ליבה אחת. מעל 4:1 ה-host עלול להיות עמוס.
הכי עמוסים על ה-ESXi — שלושת השרתים שצורכים הכי הרבה CPU על אותו host (מי "השכן הרועש").
מתי זה שימושי
כשהשרת איטי אבל הוא עצמו לא עמוס: בדוק אם ה-host שלו עמוס, כי אז הבעיה אצל השכנים ולא אצלו. הנתון רגעי ולא נשמר.
💽 דיסקים — לייטנסי, IOPS ו-MB/s
לייטנסי (Read / Write)
כמה זמן, במילישניות, לוקח לדיסק לענות לקריאה או לכתיבה. מתחת ל-20ms תקין · 20–30ms איטי · 30ms ומעלה בעייתי. כמה שהמספר נמוך יותר, זה טוב יותר. בריחוף רואים גם את השיא ב-5 הדקות האחרונות.
IOPS (R / W)
כמה פעולות קריאה / כתיבה לשנייה הדיסק מבצע.
MB/s (R / W)
כמה נתונים לשנייה עוברים (קריאה / כתיבה).
Datastore
המקום באחסון שעליו הדיסק הוירטואלי יושב.
שים לב
הלייטנסי הוא מה שהשרת חווה (כפי שה-ESXi רואה), כולל המתנה בתור של ה-host. הנתון חי, ממוצע של 5 דקות אחרונות, ולא נשמר.
📈 הגרף של כל שרת
הקו הכחול / הסגול
פיק ה-CPU (כחול) ופיק ה-RAM (סגול), הערך הגבוה ביותר בכל שעה (בטווחים ארוכים — בכל יום).
הקו האדום המקווקו
סף ה-CPU שהוגדר.
קווים כתומים — גיבוי
מתי נוצר גיבוי של השרת ב-Veeam. אם יש גם פס שקוף, זה משך הגיבוי. ריחוף מציג שעה או טווח שעות, שם ה-job ושרת הגיבוי. כך אפשר לדעת אם קפיצה בעומס נגרמה מגיבוי.
קווים טורקיז — רפליקציה / סנאפשוט
נקודות של jobs מסוג רפליקציה (למשל כל שעה). מוצגים רק אם סימנת "הצג רפליקציה / סנאפשוט".
"לא נמצא גיבוי לשרת"
לא נמצא אף גיבוי של השרת בשרתי הגיבוי בטווח הזה. אם מופיע "לא ענו", אחד משרתי הגיבוי לא הגיב בזמן.
🔎 טיפ: איך מגלים למה שרת איטי
1. CPU % / RAM % של השרת גבוהים? → השרת עצמו צריך יותר משאבים.
2. CPU Ready גבוה? → ה-host עמוס, כנראה יותר מדי שרתים עליו.
3. לחץ זיכרון (swap / balloon)? → ל-host חסר זיכרון.
4. לייטנסי דיסק גבוה? → בעיה באחסון.
5. קווים כתומים בזמן הקפיצה? → הגיבוי גרם לעומס.
6. כלום מהנ"ל? → ייתכן שהבעיה בתוך השרת (אפליקציה, מערכת הפעלה) או ברשת.
